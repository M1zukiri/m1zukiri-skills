# domains/dsp-parity

**适用**：有 MATLAB / 参考实现，需要移植或用另一种语言重写，并要求数值一致的信号处理项目。
**来源**：cpp0623、cpp0706、dbi-dsp、mdzct-xqwaq、cuda-dsp-port、simplesimulation、keysight-pam4
七份文档共同出现的工作形态。

<!-- anchor: acceptance -->
## 验收标准

- 有参考实现时，验收标准就是**与参考实现的数值偏差阈值**，写进文档与验收脚本。
- 阈值必须**分层**：纯函数层 / 系数层 / 信号处理原语 / 插值 / 最终指标，各给不同量级。
  一个阈值管全链，会让某一层的偏差被下游抵消或被放大而看不出来。
- **阈值按测试项分别约定，不得把某一测试项的门限自动套用到另一测试项。**
  （例：0.1 dB 的容差不等于可用于 TDECQ。）链内分层容差与跨测试项不借用，是两条独立的规则。
- 阈值必须标注是**目标**还是**实测**。把目标写成「已达成」会让验收结论失效。

<!-- anchor: bias-attribution -->
## 偏差归因

- 有偏差必须归因到具体来源：随机数算法、FFT 路径、插值方式、迭代次数、索引基准、量纲。
  只报「差多少」的验收不算完成。
- 放弃或回滚的优化必须记录，并写明原因。**精度漂移是一等驳回理由。**
- 偏差的计数与容差是两件事，分开写。

<!-- anchor: traceability -->
## 可追溯

- 函数名、变量名、返回字段与参考实现**同名**；L1 函数沿用参考实现原名。
- 每处索引基准转换（1-based → 0-based）注释原文行号。
- 参考实现**只读**、不修改。版本谱系与「当前对应哪一版」必须写在项目文档里。
- 测量口径写明标准条款与简化项；符号约定（如色散正负）与单位换算表定死。

## 约定先行
