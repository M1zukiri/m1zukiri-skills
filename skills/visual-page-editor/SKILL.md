# visual-page-editor（页面元素的指认与批注）

用户看到页面上的问题，但说不清是哪个元素、该改哪一行。本 skill 把「指认」变成可点选的操作，并把元素对应回生成它的源码位置。

## 何时使用

用：

- 用户对某个 HTML 页面提出修改意见，但位置只能靠形容词描述（「那个表头」「右上角那块」「这张图的说明」）
- 页面由生成器或模板产出，直接改 HTML 会在下次重新生成时被覆盖
- 需要把「界面上的元素」与「源码里的行」建立可核对、可复核的对应关系

不用：

- 截图加箭头就够说清的（直接截图更快）
- 页面没有可改的源码（例如抓取存档的网页）——批注不出坐标，没有意义

## 工作流

### 1. 生成批注副本

```bash
python scripts/make_annotator.py <页面.html> [输出.html] [--source <源码文件>]...
```

副本是**单文件、零外部依赖**，可直接用 `file://` 打开。原页面**不做任何修改**（脚本只读它）。脚本会打印页面特征与坐标来源：

```
副本已生成: q1.annotate.html (0.78 MB)
  页面特征: canvas 16 · svg 4 · details 0 · 控件 2 · script 1 · 元素约 605
  [提示] 含 16 个 canvas：像素在进入批注时移植；图形若依赖参数，请先在原生模式调好参数再进入
  [提示] 含 2 个交互控件：快照内控件不可交互（值保留、拖动无效），请在进入批注前把参数调到位
  页面指纹: sha256 dc5ad5e9fdcf…  (746383 bytes)
  坐标来源: 离线反查 562 个元素（源文件 5 个）
  生成器指纹: 页面未声明（非 generate_page.py 产物，或页面版本过旧）
```

### 2. 用户在副本上批注

用户在浏览器里打开副本，点选元素、写意见、导出 JSON。

| 操作 | 效果 |
|---|---|
| `Alt+A` 或左下角悬浮按钮 | 进入 / 退出批注模式 |
| 单击元素 | 弹出该位置的所有候选元素（可见项优先，「其他」折叠），点列表项加入待批注 |
| `Shift` + 单击 / 拖拽 | 区域批注 |
| `Ctrl` + 单击 | 位置批注 |
| 点大头钉 | 固定当前区域，防止误点丢失上下文 |
| `Esc` | 先关闭列表，再退出模式 |
| 「导出」 | 下载 `annotations.json` |

列表、图钉、高亮框都会跟随滚动。列表可用标题栏拖动避开遮挡。

### 3. agent 按坐标改源码

读批注 JSON，对每条批注的 `targets[].src.coord` 定位源码，改完后重新生成页面并校验。

**先做版本对账**：批注里的 `page.sha256` 是批注时所依据的页面哈希。重算当前页面的哈希，不一致说明页面已重新生成，批注可能基于旧版本——**此时先向用户确认，不要直接照改**。

## 坐标体系

每个元素携带一个 `data-src` 字符串，粒度到具体子元素：

| 形式 | 含义 | 稳定性 |
|---|---|---|
| `scripts/x.py:84` | 项目源码的第 84 行 | 稳定 |
| `results/x.json#metrics.ber` | 结果数据里的字段 | 稳定 |
| `README.md#假设与局限` | 文档章节 | 稳定 |
| `gen:STAGE_META.matched_filter` | 生成器内的语义锚点 | 可 grep，不随行号漂移 |

`gen:` 前缀表示来源在**生成器**里而非项目源码里。生成器行号故意不写：改一次生成器所有行号就全废，而页面和基于页面的批注不会。锚点可以 grep，行号不能。

**粒度示例**：同一个方块，点方块本身得到 `scripts/x.py:51`（改行为），点方块里的中文标签得到 `gen:STAGE_META.<func>`（改文案）。

批注 JSON 里 `src` 的结构：

```json
{
  "coord": "page_template.html:173",
  "origin": "index",            // "data-src" = 生成器注入；"index" = 离线反查
  "own": true,                  // 该元素自身带标注（false = 继承自最近祖先）
  "confidence": "high",         // 仅 origin=index 时存在
  "why": "文本唯一命中",
  "lineText": "<h2>系统模型与仿真链路<span class=\"tag\">题面条件</span></h2>"
}
```

`lineText` 是坐标那一行的原文，**先看它再决定怎么改**——它能立刻暴露坐标是否指对了地方。

## 坐标来源自动分流

脚本自行判断，**不需要用户或 agent 预先分类**：

| 页面情况 | 来源 | 实测 |
|---|---|---|
| 自带 `data-src`（生成器注入） | 直接读，跳过反查 | 准确率 100% |
| 无 `data-src` | 离线反查，按 CSS 路径匹配 | 模板组装型页面覆盖 100% |

离线反查的默认源码集合是**页面同目录 + `src/` 子目录**下的 `.py`/`.js`/`.mjs`/`.ts`/`.html`。单文件可视化页通常是「组装脚本 + 模板 + 前端逻辑」三者拼成，只喂组装脚本会漏掉绝大部分字面量：某页面只喂组装脚本时反查命中 52/562，补上模板与前端逻辑后达到 562/562。

**若反查结果不理想，先检查源码集合是否齐全**，用 `--source` 显式指定。

## 让生成器产出坐标（可选，推荐）

页面由自己的生成器产出时，让生成器在渲染每个元素时写出 `data-src`，比离线反查更准（生成器本来就知道每段 HTML 的来源）。

约定只有一条：**元素上写 `data-src`**。子元素不写也可以，标注会向上继承到最近带 `data-src` 的祖先。

```python
def _src(coord: str) -> str:
    return f' data-src="{_html_escape(coord)}"' if coord else ""

# 项目源码位置用 文件:行号（稳定，不随生成器改动漂移）
f'<div class="stage"{_src(f"scripts/{file}:{line}")}>'
# 生成器自己的文案用语义锚点（可 grep，不写行号）
f'<span{_src(f"gen:STAGE_META.{func}")}>{label}</span>'
```

参考实现见另一些项目的 `generate_page.py`（被处理的页面自带的生成器），它覆盖了一份完整的注入点清单。

## 已知边界

- **快照内交互控件失效**：`cloneNode` 不复制事件监听，所以 `<input>`/`<select>`/`<button>` 在批注模式下拖动无反应（值仍在）。**需要调参数时，先用原生模式调好，再进入批注模式**。脚本与进入提示都会报出失效控件数。
- **canvas 像素需要移植**：克隆不复制 canvas 像素。脚本用 `drawImage` 逐个移植，进入时会报出移植数量。
- **约 8% 元素无坐标**：`<head>`/`<style>`/`<title>`/`<meta>` 等结构性节点与空态兜底元素，不可批注或无需溯源。
- **离线反查的「祖先继承」只回答「改哪个函数」**：表格单元格与动态模板片段自身没有字面量，只能继承容器位置，不精确到行。
- **`<td>`/`<th>` 带 `kind: "data"` 提示**：值来自数据源，改模板不生效。
- **副本不会自动失效**：源页面重新生成后副本仍是旧的。对账靠 `page.sha256`（见工作流第 3 步）。
- **自动化验证时不要调 `exportJSON()`**：它内部 `a.click()` 触发文件下载，无头浏览器会挂起等待。改为读 `window.__VPE__.state.annotations`。

## 自检

生成副本后可用 `--selftest` 验证运行时与页面是否兼容：

```bash
python scripts/make_annotator.py <页面.html> <输出.html> --selftest
# 无头浏览器读取 #VPE_SELFTEST 的内容（JSON）
```

它检查快照建立/还原、canvas 移植前后 `toDataURL()` 是否一致、UI 挂载、图钉对齐、滚动跟随，以及 JS 异常。
