# visual-page-editor（页面元素的指认与批注）

用户看到页面上的问题，但说不清是哪个元素、该改哪一行。本 skill 把「指认」变成可点选的操作，并把元素对应回生成它的源码位置。

## 何时使用

用：

- 用户对某个 HTML 页面提出修改意见，但位置只能靠形容词描述（「那个表头」「右上角那块」「这张图的说明」）
- 页面由生成器或模板产出，直接改 HTML 会在下次重新生成时被覆盖
- 需要把「界面上的元素」与「源码里的行」建立可核对、可复核的对应关系

不用：

- 截图加箭头就够说清的（直接截图更快）
- 页面没有可改的源码（例如抓取存档的网页）——批注不出坐标，没有意义

## 工作流

### 1. 生成批注副本

```bash
python scripts/make_annotator.py <页面.html> [输出.html] [--source <源码文件>]...
```

副本是**单文件、零外部依赖**，可直接用 `file://` 打开。原页面**不做任何修改**（脚本只读它）。脚本会打印页面特征与坐标来源：

```
副本已生成: q1.annotate.html (0.78 MB)
  页面特征: canvas 16 · svg 4 · details 0 · 控件 2 · script 1 · 元素约 605
  [提示] 含 16 个 canvas：像素在进入批注时移植；图形若依赖参数，请先在原生模式调好参数再进入
  [提示] 含 2 个交互控件：快照内控件不可交互（值保留、拖动无效），请在进入批注前把参数调到位
  页面指纹: sha256 dc5ad5e9fdcf…  (746383 bytes)
  坐标来源: 离线反查 562 个元素（源文件 5 个）
  生成器指纹: 页面未声明（非 generate_page.py 产物，或页面版本过旧）
```

### 2. 用户在副本上批注

用户在浏览器里打开副本，点选元素、写意见、导出 JSON。

| 操作 | 效果 |
|---|---|
| `Alt+A` 或左下角悬浮按钮 | 进入 / 退出批注模式 |
| 单击元素 | 弹出该位置的所有候选元素（可见项优先，「其他」折叠），点列表项加入待批注 |
| `Shift` + 单击 / 拖拽 | 区域批注 |
| `Ctrl` + 单击 | 位置批注 |
| 拖浮层标题栏（工具栏最左侧是 `⠿`） | 移动工具栏、待批注面板、候选列表、批注列表 |
| 「让路」按钮，或按 `` ` `` | 所有浮层变淡并放行鼠标，点击穿透到页面；右下角「恢复浮层」或再按 `` ` `` 还原 |
| 点大头钉 | 收起当前选择。在别处点选会直接开始新的选择，不需要先解除固定 |
| `Esc` | 先关闭列表，再退出模式 |
| 「导出」 | 下载 `annotations.json` |

列表、图钉、高亮框都会跟随滚动。

浮层会压住页面元素，被压住的位置点不到——**先拖动挪开，或按「让路」让它整体穿过去**。

### 3. agent 按坐标改源码

读批注 JSON，对每条批注的 `targets[].src.coord` 定位源码，改完后重新生成页面并校验。

**先做版本对账**：批注里的 `page.sha256` 是批注时所依据的页面哈希。重算当前页面的哈希，不一致说明页面已重新生成，批注可能基于旧版本——**此时先向用户确认，不要直接照改**。

**读 `confidence` 决定信到什么程度**：

| confidence | 含义 | 怎么用 |
|---|---|---|
| `high` / `medium` | 锚点唯一命中，且与所在区域归属一致 | 可直接照着改 |
| `region` | 自身没有锚点，只确定到区域（如某个弹窗的渲染函数） | 去该文件里找具体位置 |
| `ambiguous` | 锚点有多个候选，区域投票未收敛 | 看 `candidates` 列出的全部候选行，逐条核对 |
| `conflict` | 自身唯一命中与区域归属矛盾，疑为通用命名误命中 | **不要直接用**，按区域归属重新找 |

`src` 为 `null` 时，按 `cls` → `cssPath` → `text` 的顺序在源码里 grep：`cls` 通常就是源码里的 class 名，`cssPath` 用来在运行时 DOM 里定位父子关系，`text` 全文用来命中 JS 模板字符串。

同时读 `rect` 与 `section`：`rect.w` 能把「太宽了」这类模糊意见变成可核对的数字（如 674 = 720px 容器减内边距），`section` 能显示几条批注其实同属一个区域、可以合并处理。

## 坐标体系

每个元素携带一个 `data-src` 字符串，粒度到具体子元素：

| 形式 | 含义 | 稳定性 |
|---|---|---|
| `scripts/x.py:84` | 项目源码的第 84 行 | 稳定 |
| `results/x.json#metrics.ber` | 结果数据里的字段 | 稳定 |
| `README.md#假设与局限` | 文档章节 | 稳定 |
| `gen:STAGE_META.matched_filter` | 生成器内的语义锚点 | 可 grep，不随行号漂移 |

`gen:` 前缀表示来源在**生成器**里而非项目源码里。生成器行号故意不写：改一次生成器所有行号就全废，而页面和基于页面的批注不会。锚点可以 grep，行号不能。

**粒度示例**：同一个方块，点方块本身得到 `scripts/x.py:51`（改行为），点方块里的中文标签得到 `gen:STAGE_META.<func>`（改文案）。

批注 JSON 里 `src` 的结构：

```json
{
  "coord": "page_template.html:173",
  "origin": "index",            // "data-src" = 生成器注入；"index" = 离线反查
  "own": true,                  // 该元素自身带标注（false = 继承自最近祖先）
  "confidence": "high",         // 仅 origin=index 时存在
  "why": "文本唯一命中",
  "lineText": "<h2>系统模型与仿真链路<span class=\"tag\">题面条件</span></h2>"
}
```

`lineText` 是坐标那一行的原文，**先看它再决定怎么改**——它能立刻暴露坐标是否指对了地方。

## 坐标来源自动分流

脚本自行判断，**不需要用户或 agent 预先分类**：

| 页面情况 | 来源 | 实测 |
|---|---|---|
| 自带 `data-src`（生成器注入） | 直接读，跳过反查 | 准确率 100% |
| 无 `data-src` | 静态索引（按 CSS 路径）+ **运行时反查**（按字面量） | 静态部分覆盖 100%；运行时生成的 DOM 由反查兜住 |

点选时先查静态索引（生成时一次算好，点选即得），没命中才走运行时反查。

离线反查的默认源码集合是**页面同目录 + `src/` 子目录**下的 `.py`/`.js`/`.mjs`/`.ts`/`.html`。单文件可视化页通常是「组装脚本 + 模板 + 前端逻辑」三者拼成，只喂组装脚本会漏掉绝大部分字面量：某页面只喂组装脚本时反查命中 52/562，补上模板与前端逻辑后达到 562/562。

**若反查结果不理想，先检查源码集合是否齐全**，用 `--source` 显式指定。**HTML 模板也要喂进去**——`id="btnOpenFile"` 这类锚点写在 HTML 里，只给 `src/*.js` 是查不到的。

## 运行时反查（覆盖 JS 生成的 DOM）

静态索引只能覆盖**静态 HTML 里已经存在**的元素。JS 运行时创建的弹窗、列表在索引里没有条目——实测某应用型页面，弹窗打开后 43 个可见元素里 0 个有坐标，而用户最想改的往往正是这些区域。

解法不是"预先遍历页面状态"（那要猜点哪些按钮、还要准备素材），而是**把反查推迟到点选那一刻**：生成时只把源码压成「字面量 → 候选位置」的倒排表，运行时 DOM 就是真身，不存在索引与状态失配，也就不需要进入状态。

四层锚点，命中即止：

| 层 | 依据 | 说明 |
|---|---|---|
| ① i18n key | 可见文本 → 文案字典反查 key → `T('key')` | 唯一性最高。需要页面暴露字典（`MC.i18n.dictOf` / `window.i18n` / `__I18N__`），探不到就跳过这层，不报错 |
| ② 文本字面量 | 元素文本是某个源码字面量的子串 | 硬编码中文靠这层 |
| ③ id | `id="…"` / `.id = '…'` | |
| ④ class | 取**候选最少**的那个 class | 合并所有 class 会让 `modal modal-wide` 退化成 `modal` 的 15 个候选 |

**只给唯一解。** 锚点命中多处时不猜：

- **区域投票**：以元素最近的有 id 的祖先把页面切块，块内每个元素各自主张来源文件（唯一命中 3 票、多候选 1 票），得票最多者为该区域的归属。
- **自身主张与区域归属矛盾 → 不采信**，标 `conflict`。通用命名（`modal-overlay` 在 9 个文件里都有）单看自身会产生看似合理实则错误的坐标，比没有坐标更危险。
- **多候选在区域内仍不唯一 → `ambiguous`**，把全部候选行列出。
- **自身无锚点（`thead`/`tr`/`td`）→ `region`**：给出区域归属文件，不给具体行。

实测（同一页面，同一批元素）：

| | 旧：只取第一个命中 | 新：四层锚点 + 区域投票 |
|---|---|---|
| 弹窗内 21 个元素 | 8 个有坐标，其中 **2 个指错文件** | 8 个有坐标且**逐个核对全部正确**，12 个区域归属，2 个 ambiguous，**0 个错** |
| 全页 129 个可见元素 | 83 个有坐标（64.3%） | **110 个有坐标（85.3%）** |

## 让生成器产出坐标（可选，推荐）

页面由自己的生成器产出时，让生成器在渲染每个元素时写出 `data-src`，比离线反查更准（生成器本来就知道每段 HTML 的来源）。

约定只有一条：**元素上写 `data-src`**。子元素不写也可以，标注会向上继承到最近带 `data-src` 的祖先。

```python
def _src(coord: str) -> str:
    return f' data-src="{_html_escape(coord)}"' if coord else ""

# 项目源码位置用 文件:行号（稳定，不随生成器改动漂移）
f'<div class="stage"{_src(f"scripts/{file}:{line}")}>'
# 生成器自己的文案用语义锚点（可 grep，不写行号）
f'<span{_src(f"gen:STAGE_META.{func}")}>{label}</span>'
```

参考实现见另一些项目的 `generate_page.py`（被处理的页面自带的生成器），它覆盖了一份完整的注入点清单。

## 已知边界

- **运行时生成的 DOM 走另一条路径**：静态索引覆盖不到 JS 运行时创建的元素（弹窗、卡片、条件渲染列表），这类元素由**运行时反查**兜住（见上文），不需要预先遍历页面状态。反查仍可能给不出具体行：结构节点（`thead`/`tr`/`td`）只能给到区域归属，通用命名会标 `ambiguous`。
- **快照内交互控件失效**：`cloneNode` 不复制事件监听，所以 `<input>`/`<select>`/`<button>` 在批注模式下拖动无反应（值仍在）。**需要调参数时，先用原生模式调好，再进入批注模式**。脚本与进入提示都会报出失效控件数。
- **`disabled` 控件会被解除**：浏览器在命中测试阶段就丢弃 `disabled` 元素，连 `mousedown` 都不派发，表现为「点不动」而不是「点了没反应」。副本在进入时于**克隆体**上解除 `disabled`，原页面不受影响、退出后恢复，并在提示里报出解除数量。
- **canvas 像素需要移植**：克隆不复制 canvas 像素。脚本用 `drawImage` 逐个移植，进入时会报出移植数量。
- **约 8% 元素无坐标**：`<head>`/`<style>`/`<title>`/`<meta>` 等结构性节点与空态兜底元素，不可批注或无需溯源。
- **离线反查的「祖先继承」只回答「改哪个函数」**：表格单元格与动态模板片段自身没有字面量，只能继承容器位置，不精确到行。
- **`<td>`/`<th>` 带 `kind: "data"` 提示**：值来自数据源，改模板不生效。
- **反查坐标只带文件名、不带目录**：`file` 字段是 basename，源码集合里存在跨目录同名文件时会指错。
- **副本不会自动失效**：源页面重新生成后副本仍是旧的。对账靠 `page.sha256`（见工作流第 3 步）。
- **自动化验证时不要调 `exportJSON()`**：它内部 `a.click()` 触发文件下载，无头浏览器会挂起等待。改为读 `window.__VPE__.state.annotations`。

## 自检

```bash
python scripts/make_annotator.py <页面.html> <输出.html> --verify
```

`--verify` 注入探针、驱动无头浏览器跑一遍、直接打印逐项结论：

```
  [自检] 运行版本 0.1.0-p9
    ✓ 进入/退出批注模式      ✓ 图钉与点击对齐
    ✓ 快照建立与还原          ✓ 点选能展开候选
    ✓ canvas 像素移植         ✓ 连续点选不被吞
    ✓ disabled 控件可点       ✓ disabled 只改副本
    ✓ 让路能穿透              ✓ 让路可还原
```

覆盖快照建立/还原、canvas 移植前后 `toDataURL()` 是否一致、UI 挂载、图钉对齐、滚动跟随、点选与提交链路、`disabled` 隔离、让路穿透，以及 JS 异常。

## 临时文件

**无头浏览器的 profile 目录是一次性垃圾，不是可复用缓存。** 每个 `--user-data-dir` 会展开约 300–900 MB，且会话之间互不复用。

- 用 `--verify`：profile 由脚本在 `TemporaryDirectory` 里创建并删除。**不要自己拼 `--user-data-dir`** —— 每拼一次就在系统临时目录里留下一个几百 MB 的目录。
- 确需自己驱动浏览器时，profile 必须指向临时目录，并在同一个 `finally` 里删除。
- 项目目录里只应留下副本 HTML 与导出的 `annotations.json`。浏览器 profile 出现在项目目录里，说明清理漏了。
