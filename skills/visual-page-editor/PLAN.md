# visual-page-editor 开发计划

> 长程开发计划。记录完整流程、各阶段验收标准与决策依据。
> 本文件属于公开同步集（`m1zukiri-skills`），**不得写入含用户名的本机路径、凭证或环境信息**。

## 1. 目标

让用户能在**已渲染的可视化页面上直接指认元素并写批注**，由 agent 将批注精确落回源码、完成修改、重新生成并校验。

解决的问题不是「找不到元素」，而是「用户看到的视觉元素与源码位置之间缺少可靠映射」。

## 2. 范围

### 做

- 把任意静态 HTML 页面转成**批注副本**（不改原文件）
- 副本上支持：元素点选、重叠元素列表、多选、位置批注、区域批注
- 批注导出为结构化 JSON，含**源码位置**与**源头类别**
- skill 指导 agent 消费批注：判定改哪一层源码 → 改 → 重新生成 → 校验

### 不做

- 不做浏览器扩展或油猴脚本（改用生成副本，零安装）
- 不修改原页面文件（原页面保持零 JS、离线自包含）
- 不做在线协作或多用户批注
- 不在批注副本里做实时预览渲染（只做「看和指认」）

## 3. 已冻结的设计决策

| # | 决策 | 依据 |
|---|---|---|
| D1 | 批注载体是**生成的副本文件**，不是浏览器注入 | 零安装；可自由改副本而不污染原页面；可在生成时烧入溯源信息 |
| D2 | 进入批注模式时建立 **DOM 快照**（克隆 + 原位替换） | 实测克隆成本可忽略；原页面零污染；退出即时还原 |
| D3 | 快照初始状态 = 克隆那一刻的实时状态（含滚动位置、折叠区开合） | 用户要求「页面默认情况和原生页面一致」 |
| D4 | 提供「全部展开」按钮，作用于快照 | 目标页面折叠区数量 4–23，必须能展开后批注 |
| D5 | 批注以 **JSON** 交付 | 读者是 agent，可解析、可校验、可承载定位字段 |
| D6 | 定位主键是**源码位置**，不是元素 id | 生成的 id 后缀会随内容变化漂移 |
| D7 | `src` 字段存**行号 + 该行原文**双份 | 行号会因源码上半部分改动而平移，需内容兜底 |
| D8 | 一条批注可绑多个目标（`targets` 数组 + `role` 字段） | 支持「一个结构、多个元素」与批量统一修改 |
| D9 | 部分覆盖不引入 `overrides`，改用多对多关系 | 同一元素可出现在多条批注中，避免嵌套结构 |
| D10 | 手势采用**模式分离**：非激活时零监听 | 与原页面互不干扰是架构保证，不靠小心避让 |
| D11 | 批注 UI 全部置于 **Shadow DOM** | 目标页面自带大量 CSS，不隔离必然互相污染 |
| D12 | 索引精确到**列表项级**（`tr`/`li`/`dt`） | 用户权衡：精确多等一分钟，胜过指认与对账反复浪费 |
| D13 | 先打透**类型 A**（纯静态页），再支持类型 B（canvas） | 类型 A 覆盖 10 个页面且结构简单，先跑通全链路 |
| D14 | 批注面板**常驻左下角**，「选择元素」与「写批注」解耦 | 浮动编辑器形成状态机，实测中造成选择与提交的状态冲突 |
| D15 | 分层判据用「是否携带语义信息」，无 id 的超大容器折入「其他」 | 以「有无尺寸」判定会让「其他」组恒为空——布局中的元素几乎都有尺寸 |
| D16 | 定点批注手势用 `Ctrl+单击`，区域批注用 `Shift+拖拽` | 用户操作习惯 |
| D17 | 以**大头钉固定当前选定区域**：列表可拖动标题栏移动（解决列表自身遮挡元素的问题）；钉子在时单击/框选不再重开选择，点钉子解锁后可重选 | 列表自身会遮挡元素；且需防止误操作丢失当前选择上下文 |
| D17b | 列表首项固定为「📍 这个位置」/「▭ 这块区域」 | 框选需同时能表达「对区域本身批注」与「选区域内元素」 |
| D18 | 待批注面板支持折叠 | 面板常驻左下角会遮挡内容，需可收起 |
| D19 | 列表元素按 `tier` 分组（head/primary/other），`other` 默认折叠 | 合并分组会丢失分层，结构性元素（html/body/main）涌上主列表 |
| D20 | 图钉／区域框／列表一律按**文档坐标**存放，滚动时重算视口位置；列表被手动拖拽后停止自动跟随 | `position:fixed` + 视口坐标会让标记在滚动后与所指内容脱节；拖拽后位置由用户决定，不应被自动改写 |
| D21 | 图钉用 emoji `📍`（U+1F4CD，垂直字形），以 `translate(-50%,-95%)` 使针尖对齐点击点 | 手绘 CSS 图钉的针线易偏离；`📌` 为斜字形，针尖在左下，需二维偏移且随字号漂移 |

## 4. 实测依据

以下数据来自对真实页面的 headless 实测（Edge headless + 注入探针），是 D2、D4、D12、D13 的直接依据。

### 4.1 快照性能

| 指标 | 4.74 MB 页面 | 0.71 MB 页面 |
|---|---|---|
| DOM 节点数 | 991 | 881 |
| 克隆 body | < 0.05 ms | < 0.05 ms |
| 替换 body | < 0.05 ms | < 0.05 ms |
| 强制重排 | < 0.05 ms | < 0.05 ms |
| DOMContentLoaded | 246 ms | 973 ms |

**结论**：页面体积几乎全是内嵌数据，DOM 结构极小（约 1000 节点）。快照方案无性能障碍。最初对「克隆慢、内存翻倍」的担心经实测证伪。

### 4.2 canvas 风险（已证实并已找到解法）

`cloneNode` **不复制 canvas 像素**。实测某页面 16 个 canvas 克隆后 `toDataURL()` 长度全部退化为同一空白值（3762），原值分别为 13058 / 14018 / 21862 / 20330。

解法为像素移植 `ctx.drawImage(origCanvas, 0, 0)`，实测：

- 移植耗时 < 0.05 ms（16 个 canvas）
- 移植后长度恢复为 13058 / 14018 / 21862 / 20330，与原值逐一致

该页面未暴露重绘入口（全局对象只有计算函数，渲染函数在 IIFE 闭包内），故**像素移植是唯一通用解法**，不依赖页面实现。

### 4.3 页面类型分布

| 类型 | 数量 | 特征 | 代表 |
|---|---|---|---|
| A：纯静态 | 10 | 零 JS、零 canvas、靠 `<details>` 折叠（4–23 个） | `projects/*/web/index.html` |
| B：JS 渲染 | 2 | 内嵌 JS、canvas 10–16 个、svg 4–8 个、含交互控件 | 单文件可视化页面 |

体积与复杂度无关：4.74 MB 页面零 canvas，0.71 MB 页面却有 16 个 canvas。

### 4.4 交互控件的固有局限

类型 B 页面含 `<input type="range">` 控件。克隆只复制 DOM，**不复制事件监听器**，因此快照内滑条拖不动。

**工作流约束（须写入 SKILL.md）**：若需批注「参数为某特定值时的状态」，必须先切回原生模式调好参数，再进入批注模式；快照会记录那一刻的状态。

### 阶段 3：源码坐标注入（类型 A 全链路）

**产出**：`generate_page.py` 的 `_src()` 注入 + `annotator.js` 的 `sourceOf()` 读取与导出。

**方案变更（相对初版计划）**

初版计划是「副本生成器离线反查源码」，即阶段 2 的 `index_elements.py`。实测覆盖率停在 **76.8%**：动态拼接内容（项目名、脚本名、`×N` 徽标）在源码里没有对应字面量，离线反查无从下手；试图补覆盖的启发式只有约 4 成准确率，已撤除。

改为**生成器主动注入**：页面本来就是生成器逐段拼出来的，它知道每个元素的来源。渲染时把坐标写进 `data-src`，覆盖率与准确率同时到顶，并省掉一次离线索引。

**坐标体系**（单属性 `data-src`，粒度到具体子元素）

| 前缀 | 形式 | 稳定性 | 用于 |
|---|---|---|---|
| 项目文件 | `scripts/_sota_common.py:51` | 稳定（不随生成器改动漂移） | stage 调用点、AST 配置 |
| 结果数据 | `results/<f>.json#metrics.<key>` | 稳定 | 指标行、KPI 卡、曲线、warnings |
| 文档 | `README.md#<章节>`、`refs/literature.md` | 稳定 | 正文、运行命令、文献 |
| 生成器锚点 | `gen:STAGE_META.<func>`、`gen:IMG_NOTES.<png>`、`gen:section.<名>` | 可 grep，不随行号漂移 | 中文标签、图注、章节标题 |

**为什么不写生成器行号**：生成器行号每次编辑都会漂移，而页面（以及基于页面做出的批注）不会。锚点可 grep，行号不可。

**粒度示例**：同一个 stage 方块内，点方块本身得到 `scripts/_sota_common.py:51`（改行为），点方块里的中文标签得到 `gen:STAGE_META.sample_ps_symbols`（改文案）。

**过程中修掉的既有缺陷**

内联 helper 函数时丢失了定义文件：`_sota_common.py` 里的调用点行号被贴到主脚本名下（`scripts/sota_high_rate.py:51` 实际应为 `scripts/_sota_common.py:51`）。`_top_level_defs` 的返回值改为携带文件名的 `_helper_map`，config 表头显示的来源路径同步纠正（3 处）。

**验收（已达成）**

- [x] 12 个类型 A 页面全部生成成功；坐标核对 11 个 **100%**，第 12 个的差异经查为核对脚本误报
- [x] **全量核对 201 项坐标 100% 通过**（stage 46 / cfg 3 / metric 30 / gen 锚点 122），逐条回读源码验证
- [x] 页面零回归：元素数 689→689、tag 序列逐位相同、属性差异仅新增 214 个 `data-src`（无移除、无值变化）
- [x] 生成器自带校验 `check_page.py` **0 issues**
- [x] 项目自带测试 43 项（`test_flow_tree.py` 23 + `test_page_features.py` 20）全过
- [x] 元素可溯源率 **91.7%**（632/689；含自身标注与祖先继承）
- [x] 端到端跑通：页面点选 → 候选列表 → 选中 → 提交 → 批注对象携带正确坐标
- [x] 单页生成耗时 78–163 ms（基线 132 ms，无退化）

**已知边界**

- 约 8% 元素无可溯源坐标：`<head>`/`<style>`/`<title>`/`<meta>` 等结构性节点，以及空态兜底 `<p>`。这些不可批注或无需溯源。

### 阶段 4：类型 B 支持（canvas + 无生成器页面）

**产出**：`make_annotator.py` 的页面特征探测与坐标来源分流、`annotator.js` 的离线索引回落。

**坐标来源分流**

| 页面情况 | 坐标来源 | 实测 |
|---|---|---|
| 由 `generate_page.py` 生成（自带 `data-src`） | 直接读，不反查 | 12 个类型 A 页面，准确率 100% |
| 手写或其他生成器（无 `data-src`） | `index_elements.py` 离线反查，按 CSS 路径烧进副本 | Q1 562/562、Q2 477/477 |

两侧的 CSS 路径算法（`elem_path` / `elementPath`）逐字一致，因此可以按路径精确匹配，不做猜测。

**默认源码集合**：页面同目录 + `src/` 子目录下的 `.py`/`.js`/`.mjs`/`.ts`/`.html`。单文件可视化页通常是「组装脚本 + 模板 + 前端逻辑」三者拼成——Q1 只喂组装脚本 `build_page.py`（9.6 KB）时反查只有 52/562；补上 `src/page_template.html`（35 KB）与 `src/app.js`（51 KB）后达到 562/562。

**验收（已达成）**

- [x] canvas 非空白：Q1 的 16 个 canvas `toDataURL()` 长度 `[13058, 14018, 21862]` 移植前后逐一致；Q2 的 10 个同样
- [x] svg 内容完整（Q1 4 个、Q2 8 个，随 DOM 克隆保留）
- [x] 快照内控件失效有明确提示：进入时 toast 报出失效控件数，并说明「需改参数请先退出」
- [x] 副本生成器对含 canvas / 控件的页面给出前置提示（canvas、svg、details、控件、script、元素数六项特征）
- [x] 类型 B 端到端跑通：Q1 选中 `h2` 得到 `page_template.html:173`，`lineText` 回读为 `<h2>系统模型与仿真链路<span class="tag">题面条件</span></h2>`
- [x] 离线反查准确率（逐条回读源码行）：high 97.5% / medium 91.5% / low 100%（Q1）；97.6% / 89.9% / 100%（Q2）。未命中项经逐条核对均为核对脚本的短词阈值所致，非索引错误

**已知边界**

- 离线反查的「祖先继承」占 Q1 的 39%（220/562）：表格单元格与动态模板片段自身没有字面量，只能继承容器的位置。它回答的是「该改哪个函数」，不是「该改哪一行」。
- `<td>`/`<th>` 一律附 `kind: "data"` 提示：值来自数据源，改模板不生效。
- 副本是独立文件，源页面重新生成后副本不会自动失效。对账靠 `page.sha256`：agent 取到批注时重算源页面哈希，不一致即说明批注基于旧版本。

**已修的既有问题**

- `listFollowsScroll: false`：`placeList()` 用硬编码的视口高度（360）做垂直钳制，把列表钉在窗口底部。滚动后锚点位移被钳制吞掉，列表与图钉、高亮框脱节（−11 vs −200）。改为按锚点的文档坐标定位、不做垂直钳制（水平仍保留左右翻转）。修复后三者位移一致为 −200，`pin` / `list` / `hl` 全部 `followsScroll: true`，其余快照与 canvas 检查不受影响。

**关于「把生成器一并放进 skill」的结论**

曾考虑把某个页面的生成器拷进 skill 以「消除分类」，实测后**不采纳**：

- 该生成器的输入约定（AST 分析 `scripts/*.py`、读 `results/*.json`、解析 `README.md`）只覆盖扫描到的 **97 个大型 HTML 页面中的 12 个**；另有项目有 `results/` 却无 `scripts/`，有项目是模板 + 组装器，还有约 15 个是抓取存档的外部网页（本就没有源码可改）。
- 会与项目内那份**活代码分叉**（原件有 43 个测试持续演进）。

分类的真正根源是**页面产生方式**（代码 f-string 拼接 vs 模板组装），不是「有没有生成器文件」，因此两条路径必须都保留。而 `make_annotator.py` 已自动判定，用户与 agent 都不需要预先分类。四类页面的详解见 `references/page-types.md`。

### 阶段 5.5：实战反馈修复（0.1.0-p9）

**背景**：skill 首次在另一个项目（应用型单文件页面）上被实际使用两轮。第二轮是真实工作流——用户在副本上批注 6 条，agent 依批注回改产品代码。反馈集中在两个可用性缺口，因此**暂停阶段 6 的对比实测**：没有这套 skill，这类批量精确批注本来就做不了，对照组不产生可比数据。改为先修明确问题。

**修复项与验收**

| # | 问题 | 处理 | 验收 |

| F1 | 只有候选列表能拖，工具栏与两个面板钉死在边缘；目标元素被压住就点不到 | 统一 `makeDraggable()`，四个浮层都可拖；新增「让路」——全部浮层变淡并 `pointer-events:none`，右下角留恢复入口 | 位移与预期逐像素一致（60,-40 / 40,-30 / 30,-20）；让路后 `elementFromPoint` 由宿主变为 `body`/`div`，恢复后重新命中宿主 |

## 7. 版本策略

三段式 `A.B.C`：

- **A**：初始 `0`，非用户明确要求不改
- **B**：每完成一个阶段递增
- **C**：阶段内每出现一个可确认的改进点递增

提交信息用 conventional commits（`feat:` / `fix:` / `docs:` / `refactor:` / `test:` / `chore:`），英文描述。

## 8. 术语

| 术语 | 含义 |
|---|---|
| 副本 | 由原页面生成的、注入了批注功能的独立 HTML 文件 |
| 快照 | 进入批注模式时克隆出的 DOM，批注操作作用于它 |
| `data-eid` | 由元素内容派生的稳定标识，用于跨会话引用元素 |
| `data-src` | 生成时烧入的源码位置标注（文件 + 行号 + 行原文 + 源头类别） |
| 源头类别 | 元素内容的来源层：模板字面量 / 生成器逻辑 / 注册表配置 / 项目数据源 |
| 类型 A / B | 纯静态页 / JS 渲染页 |
| targets | 一条批注所绑定的元素集合，首项为 anchor |
