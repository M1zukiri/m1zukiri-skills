# meeting-transcript-correction（会议转写校正）

会议转写校正的目标不是「写出一份漂亮的会议记录」，而是**在证据约束下，把听错、漏听、错位的地方还原到可引用的程度，同时让读者一眼看出哪些是讲者说的、哪些是推断的**。

转写稿通常同时存在三类信息：讲话内容（只有录音/上下文能证）、现场幻灯片（照片能证）、领域常识（只能用来提假设）。把三者混在一起，是这类任务最大的错误来源。这个 skill 的流程就是为拆开它们设计的。

## 输入与产出

**输入**（尽量收集齐，缺哪项就在产物里写明）：

| 材料 | 用途 |
| --- | --- |
| 原始转写 `转写.md` / `transcript.json` / `timeline.csv` | 逐句时间戳、声纹编号、原始 ASR 文本；**永远不覆盖** |
| 现场照片（PPT、白板、名牌、背景板） | 标题、讲者、机构、术语、模型名、数字、结论原句 |
| 会议议程 / 官网 / 手册 | 场次、讲者身份、单位、正式题目 |
| 讲者主页、论文、标准、公司官网 | 术语、缩写、已发表成果、数据口径 |
| 已有的自动纪要 / 汇总转写 | 交叉核对；通常也是需要联动修订的下游文件 |

**产出**（默认三件套，放在场次目录下）：

1. `转写_校正版.md` —— 信息表、中文摘要、逐句校正（含置信度）、幻灯片要点、存疑清单。
2. `校正说明.md` —— 方法与证据等级、逐类订正依据、数字与结论补全、缺失补全、存疑、外部来源、文件联动。
3. `幻灯片原文.md` —— 照片逐页文字提取，遮挡/模糊处标 `(?)`，是前两份的原始证据。

同时按需更新 `会议纪要.md` 对应小节、汇总 `转写记录.md` 的场次说明与发言人表，并在原始 `转写.md` 文首加指针。**原始 ASR 正文不改**；派生文件（纪要、汇总）要改就在该节注明「已按校正记录修订」。

模板见 `references/output-templates.md`；完整规则、证据等级、错误分类与反例见 `references/rules.md`。在动手前先读 `references/rules.md`，尤其是「说话人口误 vs 转写错误」和「反例」两节。

## 转写修改准则（v1.1，经用户确认的修订版）

> 本节是准则本体。无法判断时，按「不改」处理。相对用户 v1.0 的三处修订见本节末；v1.0 原文存档在 `references/rules.md` 附录。

### 只针对以下内容修正或补充

- 因转写时的词句错误，导致文段表述与上下文脱节或相冲突的；
- 因转写时的词句丢失，导致文段缺少语法结构、无法通顺理解的；
- 因转写时的识别问题，导致文段中的指标、数据等表述与图片或公开资料明显不符的。
  （「看起来不符合常识」只能触发存疑标记，不能单独作为修改依据。）

### 以下情况可以保留

- 虽然出现了可能的词句错误，但不能确认原意、从上下文也无法推断的；
- 丢失了与文段整体主旨相关程度不高的信息，且文段本身仍然相对完整可读的。

### 修改动作至少满足以下条件之一

- 修改后的词汇或语句与原先文本在发音、字母序列、词边界或术语上接近；
- 修改后的词汇或语句没有在原先文本里出现，但属于可唯一确定的语法结构（冠词、介词、系动词、重复词等）；实词补全需另有一类证据；
- 修改后的数据（或专名、术语）来源于转写中同一部分的图片信息；图片只证明页面/白板这样写，不证明讲者这样说，按片段补全处标 `〔补〕`；
- 修改后的数据来源于网络等公开平台上的权威信息，如学校、机构官网、论文主页、标准组织等；
- 修改动作由用户本人指定。

### 实施时必须同时满足（必要条款，不替代上面的条件）

1. **不新增信息**：只还原讲者说过的话，不借修正补进讲者没说过的事实、观点或因果。
2. **最小编辑**：能改一个词就不改一句；能保留原句结构就不重写。语法通顺但风格不佳的句子不改。
3. **区分转写错误与说话人口误**：讲者自己说错的事实不改，必要时加注「讲者原话如此」；校正的是「听写」，不是「真理」。
4. **区分幻灯片与口播**：幻灯片能证明「页面上这样写」，不能证明「讲者这样说过」。主持人念的题目、讲者临场改的题目，即使与幻灯片不同，也各自保留。
5. **数据必须有证据**：数字、单位、倍率、指标只能改到图片或权威来源能支持的程度；「显然不合理」只用于标记待核，不能作为改数依据。
6. **保留痕迹**：无法复原处保留原文并标 `〔?〕`；补全处标 `〔…〕`；不删除读不懂的碎片。
7. **记录每一步**：每条修改记「位置 / 原文 / 校正 / 类别 / 依据 / 置信度」，让第三人能复核、能回滚。
8. **不靠模型记忆**：公开来源必须给 URL 与来源层级；打不开就写「未找到」，不把记忆当证据。
9. **多候选不装确定**：两个候选都合理时，列首选 + 备选，或保留原文并注明歧义。
10. **独立复核**：至少让另一个人/agent 只读产物和证据挑错，重点查「推断被写成事实」和「幻灯片被当成口播」。

### 相对 v1.0 的三处修订

1. **「发音接近」扩展为「发音、字母序列、词边界或术语接近」**。理由：缩写（`Ot` → `OLT`）、词边界（`a fan` → `FAN`）、数字读法（`1616` → `16-QAM`）与专名远音（`Jing Wenzhao` → `Junwen Zhang`）都不属于严格同音，旧条件会把它们挡在合法修改之外。此类线索单独使用时置信度不超过「中」。
2. **「语法上唯一确定」限定为功能词与结构词**。理由：语法能唯一确定的是冠词、介词、系动词、重复词等结构；实词往往有多种补法（`be honest with the channel limit` 可补的动词不止一个），不能仅凭语法猜，必须有图片、权威来源或发音线索。
3. **数据条款从「显然不符合实际或常识」改为「与图片或公开资料明显不符」**。理由：常识会误伤（647M 用户、5580 GHz 增益带宽积、22 个月翻倍都反直觉但正确）；常识只触发存疑标记，改数必须落到图片或权威来源。同时把图片的适用范围明确到专名与术语，并保留「幻灯片≠口播」的边界。

## 工作流

### 阶段 0：建立基线与边界

- 在建 git 仓库的目录里工作；先提交「校正前」基线，保证可回滚。
- 确认任务边界：只改哪一场？哪些文件是原始件（不改）、哪些是派生物（可改并注明）？
- 记录开始时间与数据来源（录音平台、抓取时间、照片编号）。

### 阶段 1：盘点材料

- 读原始转写、`transcript.json`（时间戳/声纹/未切分原文）、`timeline.csv`、已有纪要、汇总转写。
- 列出场次边界、发言人编号、每场对应的照片编号区间。
- 先标出可疑段：专名、机构、缩写、数字、单位、模型名、术语、跨句指代、与幻灯片明显不符处。

### 阶段 2：先把图片变成文字证据

- 用 `scripts/crop_slides.py` 裁剪幕布区域并放大（3–4 倍；小字再二次裁剪），再用看图工具读。
- 逐张记：标题、正文逐字、数字与单位、图例、脚注、模型名、作者署名。模糊/遮挡标 `(?)`，按片段合并的标 `〔补〕`。
- 不要在这一步「顺手」修转写；先把证据固定下来。

### 阶段 3：逐条判定

对每条可疑转写，按 `references/rules.md` 的决策树走：

1. 是转写错误、说话人口误，还是内容本身正确？
2. 若修改，属于哪一类证据（发音/语法/图片/权威来源/用户指定）？
3. 是否满足必要条款（不新增、最小编辑、保留痕迹）？
4. 置信度：高（含义有图片/权威来源直接支撑）/ 中（由术语与上下文还原）/ 低（仅大意）。
5. 改不了就保留 + 标记，并在存疑清单里写「为什么不能定、什么材料能定」。

### 阶段 4：产出校正版

- 信息表：讲者、单位、题目、场次、主持人、其他发言、时长、照片。
- 中文摘要：按报告结构重写，数字与结论只写有证据的部分；口播补充与幻灯片结论分开写。
- 逐句校正表：时间、说话人、校正后文本、置信度、依据/主要修正。
- 幻灯片要点表：只放确实可读或明确标 `〔补〕` 的句子。
- 存疑清单：按「现状 / 可能的解法」列。

### 阶段 5：产出校正说明

- 结论概要：讲者身份、题目、术语、数据、仍存疑各一段。
- 方法与证据优先级：照片 > 原始转写 > 官方资料 > 标准/术语 > 上下文语法。
- 逐类订正：身份/题目、术语缩写、数字单位、结论与缺失补全。
- 外部来源：每条给 URL、来源层级（论文/官方页/新闻/标准）、可核到什么程度。
- 存疑与联动：哪些不能定、哪些文件被改、原始件如何保留。

### 阶段 6：自检

- 跑 `python scripts/check_corrections.py <校正版> <校正说明> ...`：断链、表格列数、置信度分布、`〔` 标记、可疑残留。
- 人工再过一遍：数字与图片逐项对；术语全篇统一；同一句在摘要与逐句表里不打架；「高」行里不夹「存疑/推断」。
- 检查所有 `〔补〕` 与 `〔?〕` 是否在说明里有交代。

### 阶段 7：独立复核

- 让只读的复核者重做三件事：不看结论、直接读原始转写与图片；逐条问「这条改动的证据是什么」；专挑「推断被写成事实」。
- 复核意见按 Blocker / High / Medium / Nit 分级，逐条修；修完在交付说明里写「已按复核意见处理」。

### 阶段 8：联动与收尾

- 更新 `会议纪要.md` 对应小节（注明已校正）、`转写记录.md` 场次说明与发言人表、原始 `转写.md` 文首指针。
- 在 `校正说明.md` 的「文件联动」节逐条申报改了哪些文件、为什么；不得有静默改动。
- 提交 git；是否推送远程由用户决定。

## 判定表（速查）

| 症状 | 处理 | 最低证据 |
| --- | --- | --- |
| 缩写被听成单词（`Ot`/`Ou`/`Moe`） | 改回标准缩写 | 幻灯片或同段术语 |
| 近音词、词边界错（`a fan`→`FAN`、`calm`→`QAM`） | 改，标低/中置信度 | 发音 + 上下文/术语 |
| 缺失功能词导致句子断裂 | 补功能词 | 语法 |
| 缺失实词 | 不猜；留 `〔?〕` | 需图片/权威来源/发音线索 |
| 专名、机构、人名错 | 改，并给官方链接 | 标题页、议程、官网、论文 |
| 数字/单位/倍率错 | 只按图片或权威来源改 | 图片/论文/标准 |
| 数字「看起来不合理」但无来源 | 不改，列存疑 | 无（仅标记） |
| 句子与上下文矛盾 | 先查上下文，再定是否听写错 | 上下文 + 证据 |
| 幻灯片说法与口播不同 | 两者并存，分别标注 | 照片 + 原转写 |
| 讲者自己说错事实 | 原样保留，必要时注「讲者原话」 | 无需修正 |
| 听不清但意思可推 | 保留大意，标 `〔?〕` | 上下文 |

## 反模式（都是从真实返工里来的）

1. **把幻灯片当成讲者原话**：主持人念的题目与幕布标题不一致时，整句替换成幕布标题，会毁掉「两个题目不同」这一事实。正确做法：两句都留，注明来源。
2. **用领域先验改术语**：讲者说 `semantic token modulation`，幻灯片标题写 `Semantic-aware token communication`，两者是不同层级的概念；不能因为「更专业」就替换。保留原词 + 注明页标题写法。
3. **用常识改数字**：647M 用户、5580 GHz 增益带宽积、22 个月翻倍都可能「看起来反常」；没有图片/论文就不许改，只能列存疑。
4. **只改字面、不留痕迹**：把整句重写后不标补全、不写依据，读者会把编辑稿当逐字稿。
5. **把无法复原处删掉求通顺**：`be honest with the channel limit` 这类句子应保留 + 标 `〔?〕`，不能换成「正确」但无据的动词。
6. **只改正文、不改纪要/汇总**：下游文件会继续传播旧错误；要么同步改并申报，要么明确标注「以校正版为准」。
7. **自己改完自己说没问题**：自校容易确认自己的猜测；必须有一次独立复核。
8. **置信度通胀**：大多数行标「高」等于没有分档；「高」只给有图片/权威来源直接支撑的句子，含补全或推断的必须降级。

## 脚本

```bash
# 裁剪幕布并放大（box 用归一化坐标；输出旁会打印每张图的路径）
python scripts/crop_slides.py images/*.jpg --out crops --box 0.28,0.36,0.76,0.71 --scale 3

# 把小字区域切条再放大，绕开看图工具的长边压缩（2x1 = 上下两半）
python scripts/crop_slides.py images/17.jpg --out crops --box 0.30,0.40,0.75,0.70 --scale 4 --tiles 2x1

# 自检：断链、表格列数、置信度分布、可疑残留
python scripts/check_corrections.py 转写_校正版.md 校正说明.md 幻灯片原文.md
```

## 验收清单

- [ ] 原始 ASR 正文未被覆盖，文首有指针。
- [ ] 每条修改都有「原文 / 校正 / 依据 / 置信度」，并能在校正说明里找到同一条。
- [ ] 所有数字与图片逐项对过；无法核实的数字没有写成确定值。
- [ ] 专名、机构、题目有官方来源或照片出处；口播题目与幕布题目若不同，两者都在。
- [ ] 所有 `〔?〕`、`〔补〕` 都有存疑或补全说明；没有为了通顺删掉的碎片。
- [ ] 「高」置信度行里没有「存疑/推断/无法复原」字样。
- [ ] 断链 0、表格列数一致、术语全篇统一。
- [ ] 派生文件（纪要、汇总、发言人表）的改动已逐条申报。
- [ ] 有一次独立复核记录，Blocker/High 已处理或明确说明未处理原因。

## 与其它 skill 的分工

- 只有音频、没有文字：先用 `audio-transcribe`，再回到本 skill。
- 需要把校正结果做成 Word/PDF/PPT：用 `office` / `docx` 系列。
- 只是润色文字、不涉及听写还原：用写作类 skill，不要用本 skill——本 skill 的首要约束是「不改讲者的意思」。
